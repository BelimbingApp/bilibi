# UI asset contract

`css/app.css` preserves the semantic tokens, font declarations, theme selection and component rules. **Commit source changes only.** Cargo builds and embeds CSS in its `OUT_DIR`; generated `app.css` is ignored by Git, so concurrent UI changes never merge generated bytes. Tailwind and its CLI are pinned to **4.3.0**. Node >=22 and npm are required on build machines; deployed apps need neither Node nor a filesystem asset layout.

- `cargo build` and `cargo clippy` build the stylesheet automatically, including mounted containers. Cargo watches the source trees and rebuilds CSS when their inputs change. The builder installs npm dependencies when they are missing or the lockfile changes.
- `./scripts/build-assets.sh` writes an ignored local `assets/app.css` for inspection. `--output <path>` chooses another destination.
- `./scripts/build-assets.sh --check` builds twice without writing a local artifact. It fails on compilation errors, different bytes across builds, or mounted utilities missing from the Platform stylesheet. CI runs it after `npm ci`, including on changes that skip Rust compilation.

The explicit `@source` paths include **every layer under apps/**, including Rust, Askama and browser adapters. Write complete utility names in source instead of constructing them from pieces. For finite dynamic variants, use a mapping of full class strings or `@source inline(...)` in the CSS entrypoint.

The class snapshot in `ui-candidates.txt` keeps the classes the shared components use available. No tool recaptures it, so add a class to it by hand when a component needs one.

`domain-candidates.txt` is the same kind of snapshot for the Supply Chain, Finance, Factory, People and People connector sources at the HEADs in `provenance.json` (`domain_sources`, keyed by container ID), so mounting those Domains changes no CSS. Recapture it from clean pinned checkouts with `node apps/base/ui/assets/capture-domains.cjs supply_chain=<dir> finance=<dir> factory=<dir> people=<dir> people_connector=<dir>`.

Mounted Domain and Extension checkouts are gitignored, which Tailwind honours, so `build.cjs` adds an explicit `@source` for each mounted Domain or Extension (a folder holding `bilibi.container.toml`); a class that only a mounted Domain uses then fails `--check`. Add that class to a Platform component or the pinned candidates in a Platform change. Icons need no candidate list: Cargo embeds their SVGs independently of Tailwind.

`css/legacy-compat.css` temporarily styles the untranslated legacy pages inside the shell's `#app-content`, using the shared semantic colors; it stops at a `[data-shared-ui]` subtree. The shell chrome itself uses source classes. Remove this compatibility sheet when the legacy pages have been translated; new components use shared source classes rather than extending it.

## URLs and browser caching

Use `bilibi_ui::Assets::url("/assets/app.css")` in shared templates to link an embedded asset with its content version.

- `src/assets.rs` owns the bounded catalogue, with digested URLs. It never resolves a request path on disk.
- Each URL carries `?v=<sha256>` of the final served bytes. Fonts are versioned before CSS, and CSS before the static specimen, so a dependency change also changes the referring asset's URL.
- The live script's version includes its debug/release reload switch. Rust assembles the hook bundle before hashing it.
- Matching versioned CSS, JavaScript, fonts and icons receive `public, max-age=31536000, immutable`. Unversioned URLs remain available with `no-store`; an incorrect version returns 404 with `no-store`.
- HTML pages, including specimens, retain `no-store`. The host negotiates gzip or Brotli for compressible responses and sends `Vary: Accept-Encoding`.
- `build.cjs` already minifies the generated CSS with Tailwind's `--minify`; Cargo needs no Node process at runtime.

The asset specimen is rendered from `templates/ui_asset_specimen.html` through the shared icon macro, then embedded with versioned asset references.

Fonts are served at `/fonts/`, favicons at `/favicon.svg` and `/favicon.ico`, and the standalone specimen at `/assets/ui-specimen.html`. The rendered component specimen at `/assets/ui-components.html` comes from `src/specimen.rs` and the shared macros.

Stylesheets reference local fonts only. Icons are inline SVGs rendered by the shared macro; no image request or CSS mask is needed.

For a quick theme inspection, open the specimen and use browser emulation for `prefers-color-scheme`. An absent `data-theme` on the root follows the system; `data-theme="light"` or `"dark"` overrides it. The specimen exercises the source button/badge classes, regular/italic fonts, semantic colors and four icon sizes. It is an asset fixture, not the Design Library or a component implementation.

- Instrument Sans: `Instrument/instrument-sans` at `7fa22308a3d0c94ee2b3cd537a1196b65db34a3e`, as recorded in the earlier snapshot. Both original WOFF2 files are copied unchanged. SIL OFL 1.1: `static/fonts/OFL.txt` (also publicly served).
- topbar 3.0.0 (`vendor/topbar.js`): the page-loading bar, copied unchanged from an earlier snapshot's `apps/web/assets/vendor/topbar.js` including its reduced-motion check. MIT, license header in the file. Served at `/assets/topbar.js`; `live.js` shows it for page-level round trips that exceed 300ms.
- Heroicons: v2.2.0 at `0435d4ca364a608cc75e2f8683d374e55abbae26`, matching the earlier snapshot's mix.lock. Original optimized SVGs and MIT license are in `vendor/heroicons/`.
- Product glyphs: extracted unchanged from an earlier snapshot's icon registry. The JSON catalog supplies the bare named actions and shell mappings to the Cargo icon build. `rows-compact` and `rows-normal` use Pictogrammers Material Design Icons (Apache 2.0); `text-indent-left` and `text-indent-right` use Bootstrap Icons (MIT). `settings-cog` and `database` are the outline icons of the same names from Tabler Icons (MIT, `TABLER-LICENSE`), with `stroke-width` set to 1.5 like the other glyphs. The Finance identity glyphs: `gmdi-money-r` is Google Material Icons `money` (rounded) without its empty bounding path, `vaadin-invoice` is Vaadin Icons `invoice`, `carbon-financial-assets` is IBM Carbon `financial--assets` without its transparent bounding rectangle (all three Apache 2.0, `APACHE-2.0`); `iconoir-receive-dollars` and `iconoir-send-dollars` are Iconoir's regular `receive-dollars` and `send-dollars` unchanged (MIT, `ICONOIR-LICENSE`); `tabler-receipt-tax` is Tabler's outline `receipt-tax` with `stroke-width` 1.5 (MIT, `TABLER-LICENSE`). Shopify Polaris `tax` is not vendored: its licence only allows applications that integrate with Shopify. Notices and full licenses are in `vendor/product-icons/`.
- Tailwind CSS: 4.3.0, MIT license in `vendor/TAILWIND-LICENSE`.

`provenance.json` records the original and vendored hashes, including the pinned Iconoir source commit. The class snapshot was produced with the pinned Tailwind scanner over an earlier project's source; it contains class candidates, not copied behavior or test code.
