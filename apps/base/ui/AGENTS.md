# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- Correct entries that work proves wrong; add new ones only by deliberate maintainer choice, never as routine task output.

## Shared UI primitives

- Use the macros in `templates/components.html` (`{% import "components.html" as ui %}`) for page, header, section heading, card, facts, stat strip, button, icon button, create button, back link, action link, badge and icon, not hand-written markup: that file is the one DOM source, mirroring Bilimbi `apps/base/ui/lib/ui/components.ex` at the pinned snapshot, so a screen that copies classes drifts from parity the next time the shared file changes. A crate outside `base/ui` reaches the same macros through the typed models in `src/components.rs` (`Button`, `Card`, `Facts`, ...), which render through the same macros.
- Name variants through the enums in `src/components.rs` (`ButtonVariant`, `BadgeKind`, `IconContext`, `IconKind`, `Chrome`, `PageVariant`, `StatKind`), not class strings; the class decisions live in their methods and in `card_flat`, `card_pads` and `stat_strip_columns`.
- Pass secondary slots (`actions`, `title_actions`) as an `Html` fragment rendered by another component, and keep `|safe` inside the shared macros only; see `src/html.rs`. Request data goes through `Html::text` or a template, never `Html::raw`.
- Askama refuses a macro nested in its own body, so a card inside a card renders the inner one through the typed `Card` model; `card_flat`/`card_pads` resolve the `p-0` and padding conventions, so do not append padding classes expecting the default to win.
- An action that submits (Bilimbi `href` + `method="post"`, such as impersonate) is an `IconButton`/`ActionLink` with `href` and `method`, which `ui.js` sends with the CSRF token and follows, never a hand-written `<form method="post">` in a list row or a `data-event` button that the owner answers with a redirect.
- Name icons through `src/icons.rs` action names (`"edit"`, `"manage"`) or `hero-*`; an unregistered name panics on purpose, and names from stored data pass `icons::renderable` first.
- Use the macros in `templates/forms.html` (`{% import "forms.html" as form %}`) for every form control (input of any type, select, textarea, checkbox, password with reveal, secret and stored-secret input, code input, combobox, multi-select, radio group, restricted value and restricted field), not hand-written `<input>` markup: that file mirrors Bilimbi `apps/base/ui/lib/ui/components/forms.ex`, and each macro takes one typed model from `src/forms.rs` (`Field`, `SecretInput`, `CodeInput`, `Combobox`, `MultiSelect`, `RadioGroup`, `Restricted`, `RestrictedField`) built with its chained setters. Field classes, described-by wiring, invalid state and the keep-current mask are decided in those models, so a page passes errors, hints and `readonly`/`disabled` and never composes control classes itself; a stored secret passes `stored()` and the model discards the value.
- A form field inside a grid or table row carries no field margin: the default `mb-4` makes rows taller than Bilimbi's.
- Take a file from the browser with `forms::file_input` over an `Uploads` the mounted state declares and returns from `LiveState::uploads` (`src/upload.rs`; browser half `assets/upload.js`), then `Uploads::consume` in the event that acts on it, never a `<input type="file">` of your own, a multipart POST route or bytes inside an event payload: the host streams, bounds and refuses files (size, kind, count) and drops them with the state, and the Design Library's File input card is the running specimen. `docs/live-pages.md` (File uploads) is the contract. Copy that specimen's wiring exactly (the typed `FileInput` renders the entry and its error, the form submits only its own action, the shared uploader owns preflight and progress): a missing oversize error was a page wiring mistake, not the control.
- Navigation is a plain link (back links, "All bills", "Download PDF", "Later entries", "Match statement lines"); only an action that changes something is a button. Header actions sit directly in the header, with no extra wrapper.
- A control the reader may not use is hidden, as in Bilimbi; do not replace it with a "You do not have permission" empty state. A refused event answers with the page's own message ("You do not have permission to post documents."), never a lower module's error text.
- The form controls' browser halves live in `assets/hooks.js` (served at `/assets/hooks.js`, loaded after `ui.js`): CodeInput, Combobox, SecretReveal, SecretClear, SecretStored and DisclosureDismiss register with `BilibiUI.registerHook` and report with `this.emit`; a server push (the owner's `LiveBody.events`) reaches a hook as a `window` event `bilibi:<name>` (`bilibi:secret:reveal` carries `{id, value, duration_ms}`). A control that reports to the server carries `data-event` (plus `data-name`/`data-option`/`data-key`), the counterpart of Bilimbi's `phx-click`; never bind listeners to a control's parts from a page.
- Edit a record's facts in place with `templates/inline.html` through the typed `InlineEdit`, `InlineLongText` and `InlineChoice` (`src/inline.rs`; browser half `assets/inline.js`, served inside `/assets/hooks.js`), not an Edit button, `/:id/edit` route or page-owned form: they own Saving…, draft recovery and version carry-back. Record outcomes with `CommitStates`/`CommitStatus` (`refusal`, `failure`); a refused or forbidden write must not return `Error::Forbidden`/`Error::Internal`, which the live transport treats as fatal and clears the page. `docs/inline-editing.md` is the owner contract.
- `/assets/ui-components.html` (`src/specimen.rs`) is the screenshot baseline for every primitive and variant; extend it when a primitive or variant is added, and keep its content mirrored in the Bilimbi reference renderer kept with the task evidence, not in this repo. Add to a section under `templates/ui_components_specimen/` (a new one goes in the `sections!` list), keeping each to a few heavy form controls, never into one page-sized template: askama inlines every macro call into one function, and the whole page as one made this crate's `rustc`/`clippy-driver` peak at 9 GB (`src/section.rs`).

## Feedback, dialogs and tabs

- Use `templates/feedback.html` (flash, `flash_group`, `connection_banners`, `alert`, `panel_notice`), `templates/dialog.html` (`modal`, `confirm_dialog`) and `templates/tabs.html` (`tabs`), or their typed models in `src/feedback.rs`, not hand-written `<dialog>`, banner or tab markup: the DOM mirrors Bilimbi `components.ex`, and `assets/css/app.css` selectors (`body:has(dialog:modal[data-owns-flash])`, the `#connection-*` ids) depend on it.
- A tab that switches a page's own view is `Tab::patch` with the page's full address plus its `tab` (`params::address`, as `apps/base/schedule/src/web.rs`), not a `Tab::button` event: Bilimbi's tabs are `patch=` links, so each view is addressable and Back returns to it.
- Never use `window.confirm` or a `data-confirm` attribute; an irreversible action renders `ConfirmDialog` while its request is pending and stops rendering it whatever the outcome. The server owns whether a dialog exists, so Escape and Cancel only raise the cancel event.
- Browser behaviour is `assets/ui.js`: a component names its controller with `data-hook`, and a controller reports intent with a bubbling `bilibi:event` CustomEvent (`detail.event` plus values), which the transport turns into a server event. The transport reports the socket with `bilibi:disconnected` (`detail.kind` `client`/`server`) and `bilibi:connected` on `window`; new controllers register with `BilibiUI.registerHook`. Do not ship Phoenix hooks (`pushEvent`, `mounted`-only lifecycles) unchanged.
- A live action that ends in `LiveBody.redirect` sets `LiveBody.flash` for the message the destination shows (`Success`, "Company created successfully."), never `notice` (the aria feedback line, lost with the page) or a cookie: the host (`apps/web/src/landing.rs`) holds it for the session's next visit to that path; contract in `docs/live-pages.md`.
- Pick a message kind by what it does: a completed write is `Success` (times out), a refusal or failure is `Error`, `Info` informs without confirming a write; only success carries auto-dismiss.
- A page's flash survives every later event on that page (table, copy-link, typing, tab, period or pin patches) until the user dismisses it or a new flash replaces it; never clear it in a generic event handler. Every page that shows a flash accepts the shared dismiss event, also for a read-only viewer (a missing handler answered "Invalid input" on 7 Factory routes).
- `/assets/ui-feedback.html` (`src/feedback_specimen.rs`) is the screenshot baseline for these; its `static/ui-feedback-driver.js` stands in for the server, so extend both when adding a variant, in a section under `templates/ui_feedback_specimen/` as above.

## Shell (`templates/shell.html`, `framed.html`, `assets/shell.js`)

- Pages never render chrome: the host wraps every discovered page through `apps/web/src/shell.rs`, which builds `ShellContext` (`src/shell.rs`) from the sealed scope (menu via effective capabilities, operator standing via `tenancy::prove_operator`, the Company label via `PartyProofs::organisation_name` on `scope.actor().organisation()`; an account has no company column, only its affiliation). Core contributes into the `notifications` slot through the `shell.notifications` embed, which Web renders and mounts as a shell panel; Base UI never imports Core.
- A hook's `apply()`/`updated()` must write the DOM only on change: `ui.js` reports any child-list mutation inside a hooked element as `updated`, so an unconditional `replaceChildren` or `textContent` write there loops forever and hangs the tab (see `renderPinnedItems` in `assets/shell.js`).
- Title a page through `Page::title` (the page name alone per operation, `"Roles"`) or, when the title names the record shown, `PageBody.title`; `templates/document.html` appends " · Business application platform" and falls back to the product name, so a title never carries the suffix or "Bilibi". Put a page's top-bar controls (Bilimbi's `topbar_actions` slot, the workspace's Add a page and Saved layouts) in `Page::topbar_actions`, which the shell renders left of the bell and omits when framed, never in the page body.
- Theme, time-display mode and pins belong to the signed-in account (`bilibi_user::presentation`, `list_pins`, saved through `/preferences` and `/api/pins`); the shell renders them into `data-theme-choice`, `data-display-mode` and `data-pins`. Do not keep them in `localStorage`, which differs per device and per account on one browser.

## Live pages (`assets/live.js`)

- A form raises its `data-event` on submit, and with `data-change` on every change too; when the two must differ (Bilimbi's `phx-change` beside `phx-submit`: validate as values change, save on Enter or Save) add `data-submit-event` naming the submit's event, as Geonames' `postcode-form` does. Do not split a form in two or make Save a `type="button"` to get there: the button then carries no values and Enter saves nothing.
- Never name a form's event `save` unless it posts Company's `{edit: {...}}` shape: `live.js` reserves that name and nests the values under `edit`, so the owner reads an empty form. Name it for the action (`create`, `save_location`).
- Raise intent with `data-event` (or a `bilibi:event`) and let the transport queue it: never keep a "pending" flag or drop input while a round trip is in flight. Every intent is sent in order with a `request_id` the server echoes; `docs/live-pages.md` is the contract. Use `data-working` for a busy label; the transport adds and lifts `aria-busy` itself.
- Give a stable `id` to any repeated fragment that holds a draft, a hook or an `<iframe>` (Company's inline editors are `company-<field>`, with underscores replaced by hyphens): a reply is patched by element id, and unkeyed siblings match by position, so a removed earlier sibling would otherwise hand a draft to the wrong form. Never rebuild `#app` or a panel with `innerHTML` from a page or hook; an iframe reloads whenever it is moved or replaced.
- A mounted panel's root element carries `id` and `data-target` (its anchor); a `data-event` button or form inside it with no `data-target` of its own then reaches that panel, so render shared `Button`, `ConfirmDialog` and `Modal` inside the root rather than adding per-control targets. A control outside every panel reaches the page.
- Place a panel's anchor as `<div id="<anchor>-slot" data-live-ignore><div id="<anchor>"></div></div>`, never `data-live-ignore` on the anchor itself: the patcher leaves an ignored element's children alone, so an ignored anchor never shows its fragment (see Company `templates/detail.html`).
- Mark a subtree the browser owns (a hook-filled status, a frame host's own text) `data-live-ignore`, the counterpart of Bilimbi's `phx-update="ignore"`: only its `data-*` attributes then follow the server. Do not fight the patcher from `updated()`; on an existing element it leaves `<details>`/`<dialog>` `open` and an iframe's `src` alone, and the browser's own dirty flags keep typed values, except in a `data-change` form, whose controls follow the server unless focused.
- Inside a workspace tile never write `history` or add entries yourself: `live.js` replaces a framed page's address changes and link clicks so Back leaves the workspace, and raises `bilibi:location` for the Tiling hook. A page whose state is its own address and that must keep its DOM (frames) across Back marks an element `data-history="params"` and handles `LiveInput::Params` (route parameters arrive in the same map), instead of being remounted; to move between its own routes it returns `LiveBody.path`, never `redirect`, which reloads the page (`apps/base/tiling/README.md`, `docs/live-pages.md`).
- Link a list row to its record with `lists::record_link` (`workspace` = the page is framed) and mark a record's page with `workspace::announce` (`templates/workspace.html`; contract `src/workspace.rs`), not a bare `<a>`: they are what lets another workspace tile follow the selection. Never post to `window.parent` from a page; the follow channel in `assets/tiling.js` owns the origin and frame checks.

## Error pages

- A failed browser request gets its page from `apps/web/src/errors.rs` (a layer over every route, using `error_document` and `debug_document` from `src/error_page.rs`), not from the handler: return a bare status or `HttpError` and never hand-render a 403/404/500 body, so the copy, the Bilimbi ids (`error-not-found`, `error-unavailable`) and the stylesheet-only document stay in one place. Word a new status in `copy_for`.
- The developer debug page (cause chain, backtrace, request, matched route) is built only when `cfg!(debug_assertions)`; never add internals to the production card, and never put credentials in `SHOWN_HEADERS`.
- The page Caddy serves while the backend is down is the static `scripts/waiting-page.html`, registered by `scripts/local-https-api.py`; it must not depend on `/assets`, which the downed backend serves.

## Operational lists

- Build a list page from `ListState` (`src/list_state.rs`: one validated `ListSpec`, `parse` on load/mount/params, `apply_filters`/`next_sort`/`put_page` on events, `to_params()` as `LiveBody.query`) and the macros in `templates/lists.html` through their models in `src/lists.rs` (`FilterToolbar`, `Table`, `Pagination`, `EmptyState`), not hand-parsed query strings or table markup: the spec bounds every untrusted value and the URL it returns is what Back and reload restore. Keep a module's existing query names and page sizes in its spec. `apps/web/examples/list-reference.rs` is the running specimen.
- Draw a list's rows with `FlexTable` (`src/flex_table.rs`, `templates/flex_table.html`), never the plain `Table`, so every list has the notch: column settings, drag reorder, row height and compact rows. Host its columns with `ListColumns` (`src/list_columns.rs`: built-ins only, arrangement lives with the mounted page) where Bilimbi's page uses `ListColumns`, and with `bilibi_grid::PageColumns` (arrangement remembered per account through `PageViews`, an address that carries `cols`/`z` wins) where Bilimbi's uses `Grid.Web.PageColumns`; `apps/base/integration/src/web.rs` is the smallest `PageColumns` host. Read the `grid` event's payload with `params::string_values`, and call `load` only when the rows changed, since it forgets an unfinished add box. A compact row is one line: leave a cell's second line out when `mode()` is `RowMode::Compact`.
