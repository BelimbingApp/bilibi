# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- Correct entries that work proves wrong; add new ones only by deliberate maintainer choice, never as routine task output.

## Mounting Domains

- A Domain is its own Git repository, `BelimbingApp/bilibi-dom-<id>`, mounted as a real nested checkout at `apps/domains/<name>`, where `<name>` is the `<id>` in snake_case (`bilibi-dom-supply-chain` mounts at `apps/domains/supply_chain`). It is not a submodule and never a symlink; Askama and path dependencies resolve from the real mount location. Mount with `git clone <repository URL or local clone> apps/domains/<name>`, then `python3 scripts/discover-modules.py` and any Cargo command (which adds the mounted crates to `Cargo.lock`).
- The Domain's root holds `bilibi.container.toml` (`id = "<name>"`, `layer = "domain"`) and one folder per module, each a crate named `bilibi-<name>-<module>` (underscores become hyphens) whose manifest inherits the workspace (`version.workspace = true`, `x.workspace = true` for Platform crates and `rust_decimal`). No `Cargo.toml`, `[workspace]` or `Cargo.lock` at the Domain's root; `fixtures/` and dot folders are never discovered. `scripts/discover-modules.py` refuses every other shape, so read its refusal rather than working around it.
- Mounted crates are ordinary Platform workspace members, so `cargo clippy --workspace --all-targets -- -D warnings` lints them; an out-of-tree composition workspace would not.
- Never commit `apps/domains/Cargo.toml`, `apps/domains/src/lib.rs` or `Cargo.lock` from a mounted checkout: the Platform's committed forms are the unmounted ones, and `--locked` does not notice extra mounted packages. Commit and push only inside the Domain's own repository, and make a Platform change with nothing mounted. `python3 scripts/discover-modules.py --check` refuses a staged or committed mounted composition or a `Cargo.lock` path package outside the Platform.
- To unmount, move the Domain out of `apps/domains`, run `python3 scripts/discover-modules.py`, and restore `Cargo.lock` (`git checkout -- Cargo.lock`, or any Cargo command without `--locked` prunes it); `git status` is then clean.
- Cross-domain flows use events (`bilibi_events`, `apps/base/events/README.md`): the publisher records a versioned event in its own `MutationTransaction`, and a subscriber in another Domain or Extension keeps its own copy of what it needs. Do not use a port, a Cargo dependency, a descriptor edge or SQL on another Domain's tables for this, because each one couples the two Domains' composition or schema. Use a port only when a caller needs an answer now from a module that may be unmounted.
- Reach a module in another Domain or Extension through an optional port (`bilibi_ports`, `apps/base/ports/README.md`): the provider contributes a `Port` and the consumer calls its ID, with no Cargo dependency or descriptor edge on the provider. Do not use a dependency or edge for this, because the consumer would then fail to compose without the provider. Do not hand-roll a registry either, because `Ports` already refuses ports named outside their module and answers `Unavailable` when the provider is unmounted.
- A Domain must not turn on features of shared crates (for example `serde_json/preserve_order`): Cargo unifies features across the workspace, so the change would reach every Platform crate.
- Every Domain route declares whether its records follow the selected desk, with a matching menu scope; use the [Domain authoring contract](README.md), not a page-owned switcher, so the top bar truthfully explains the page. A Domain owns no CSS or JavaScript. Classes come from the Platform stylesheet: `apps/base/ui/assets/domain-candidates.txt` pins every class the Supply Chain, Finance and Factory sources use (HEADs in `provenance.json`), and `build.cjs` scans each mounted Domain, so `./scripts/build-assets.sh --check` must pass while mounted. A class it fails on is a Platform change made with nothing mounted (add the class to a Platform component or the candidates, then run `--check` and commit the source change; generated CSS is ignored and built by Cargo, see `apps/base/ui/assets/README.md`), never a Domain-side stylesheet; Tailwind silently skips gitignored mounts, which is why `build.cjs` names them.
- Every Domain repository's CI is `docs/domain-ci/ci.yml` (copy to `.github/workflows/ci.yml`, with the Platform SHA in `.github/bilibi-revision`); it mounts the repository and runs `scripts/domain-ci.sh`. Run that script locally, with `DATABASE_URL` on an empty PostgreSQL 18 database, to reproduce CI. Do not hand-roll a different gate list.
- A company build pins its composition: with the Domains mounted and committed, `python3 scripts/discover-modules.py --pin` records the Platform and Domain HEADs, the release tag each is at, and the resolved `Cargo.lock` in `.local/composition/` (ignored). On a fresh checkout at the pinned Platform SHA, with each Domain cloned at its pinned HEAD, `--restore` refuses any drift and puts the pinned `Cargo.lock` back, so `cargo build --release --locked` is reproducible.
- Pin before you build, never after: `apps/web/build.rs` compiles the pin into the program, which is what `bilibi-web status` and the status bar show (`docs/versions.md`). A Domain's version is its `vX.Y.Z` tag, so clone with tags (a shallow clone without them shows the Domain as untagged). Read the host-supplied `bilibi_module_registry::Composition` through `bootstrap.composition`; do not read `.local/composition` or run Git at run time.
- A Domain change keeps its notes in its own module README, never the root README or AGENTS.md. In a shared file (`fixtures/walkthrough`, `Cargo.toml`) put the change in its own block at the end, so parallel work does not clash on merge.
- Use `bilibi_currency::Currencies` (`apps/core/currency/README.md`), not a free-text currency code, your own decimal-places list or a rate table of your own: it is the one ISO 4217 list, the tenant's enabled currencies and the one `convert`, which names the rate, its date and how it was found, and refuses (`NoRate`) instead of assuming 1. Offer `Currencies::combobox` for the control and call `check` on the write's transaction for a new assignment.
